# 内核子系统关系

FreeRTOS-Kernel 的各个子系统并不是彼此孤立的文件。它们共享调度器、链表、临界区、任务通知和移植层接口。理解这些关系，比单独背 API 更重要。

## 任务调度器

调度器位于中心位置。无论是队列、信号量、事件组、定时器还是 Stream Buffer，只要涉及“任务等待某个条件”和“条件满足后唤醒任务”，最终都要回到 `tasks.c` 改变任务状态。

调度器负责维护任务在哪个状态列表中、哪个任务应该运行、tick 到来时谁到期、是否需要抢占当前任务，以及在 SMP 场景下哪个 core 应该 yield。

## 队列

队列是 FreeRTOS 中最通用的通信结构。普通队列按值复制数据，适合在任务和任务、任务和 ISR 之间传递固定大小元素。

队列对象内部保存两类信息。

一类是数据缓冲区和读写指针，用来保存队列内容。

另一类是等待发送和等待接收的任务列表，用来在队列满或队列空时阻塞任务，并在条件变化时唤醒合适的等待者。

队列 API 有普通版本和 `FromISR` 版本。ISR 版本不能阻塞，只能尝试操作并告诉调用者是否唤醒了更高优先级任务。

## 信号量

信号量复用了队列实现。

二值信号量可以理解成长度为 1、元素大小为 0 的队列。它不传输数据，只表达“资源或事件是否可用”。

计数信号量可以理解成长度大于 1、元素大小为 0 的队列。队列中当前消息数就是信号量计数。

因为不需要复制用户数据，信号量路径主要操作计数和等待列表。

## 互斥量

互斥量也复用 `Queue_t`，但语义不同。互斥量需要记录当前持有者，并支持优先级继承。

优先级继承用于降低优先级反转风险。当低优先级任务持有互斥量，而高优先级任务等待这个互斥量时，内核可以临时提升持有者优先级，让它更快运行并释放互斥量。

递归互斥量还会记录同一个任务重复获取的次数。释放次数与获取次数匹配后，互斥量才真正变为可用。

## 事件组

事件组用一个整数位图表达多个事件位。任务可以等待任意一个位成立，也可以等待所有指定的位都成立。

事件组适合表达“多个条件组合”。例如一个任务等待网络已连接和时间已同步，或者等待多个外设中任意一个完成。

事件组不携带数据，只携带位状态。它的等待列表中不仅要记录等待的任务，还要记录该任务等待哪些 bit、是等待全部还是任一、退出等待时是否清除 bit。

## 软件定时器

软件定时器不在中断中直接执行用户回调。它由 Timer 服务任务统一驱动。

其他任务调用启动、停止、重置、修改周期等 API 时，本质上是把命令发送到定时器命令队列。Timer 服务任务收到命令后修改定时器列表。

定时器到期后，Timer 服务任务调用用户回调。如果回调执行太久，会影响其他软件定时器和挂起函数调用，因此回调应尽量短小，不应执行长时间阻塞操作。

`xTimerPendFunctionCall()` 也依赖 Timer 服务任务。它可以把一个函数调用延后到 Timer 服务任务上下文执行，常用于从 ISR 请求稍后执行较重的工作。

## Stream Buffer

Stream Buffer 面向字节流。它适合一个写入者和一个读取者之间传输连续字节，例如串口接收缓冲。

与队列相比，Stream Buffer 不把数据切成固定大小元素。写入者可以写入一段字节，读取者可以按需要读出一段字节。

Stream Buffer 主要依赖任务通知唤醒等待的一方，而不是像队列那样维护两条通用事件等待列表。因此它更轻量，但使用场景也更受约束。

## Message Buffer

Message Buffer 建立在 Stream Buffer 机制之上，但保留消息边界。每条消息会带长度信息，读取时一次取出完整消息。

它适合传递长度不固定但必须保持边界的数据，例如协议包、日志记录或控制消息。

如果只是传输固定大小对象，普通队列通常更直接。如果传输连续字节流，Stream Buffer 更合适。如果传输变长消息，Message Buffer 更合适。

## 协程

协程是 FreeRTOS 的可选旧机制，主要用于 RAM 极小的设备。协程没有独立栈，切换开销和内存成本低，但编程模型限制更多。

现代项目如果资源允许，通常优先使用任务。协程代码仍保留是为了兼容已有用户和极端资源场景。

## 子系统之间的典型协作

队列发送数据时，如果有任务等待接收，队列子系统会调用调度器接口把等待任务移回就绪态。

事件组设置 bit 时，如果某些任务等待条件满足，事件组会解除这些任务的阻塞。

软件定时器命令通过队列传递给 Timer 服务任务。Timer 服务任务本身也是一个普通 FreeRTOS 任务，受同一套调度规则管理。

Stream Buffer 写入数据后，如果读取任务正在等待，写入端会通过任务通知唤醒读取任务。

所有这些路径最后都遵循同一个原则：对象判断条件是否满足，调度器改变任务状态，移植层完成实际上下文切换。
