# 内核运行逻辑

FreeRTOS-Kernel 的运行逻辑可以从“任务如何被调度”这条主线理解。应用创建任务和内核对象后，调度器启动，之后系统在任务、ISR 和内核对象之间不断发生阻塞、唤醒、抢占和上下文切换。

## 启动前

应用在启动调度器之前通常会做三类工作。

1. 提供 `FreeRTOSConfig.h`，配置 tick 频率、最大优先级、是否启用抢占、是否启用软件定时器、是否支持动态或静态分配等。
2. 创建任务、队列、信号量、互斥量、事件组、定时器或 stream buffer。
3. 调用 `vTaskStartScheduler()` 进入 FreeRTOS 调度。

动态创建对象时，内核会通过 `pvPortMalloc()` 申请内存。具体使用哪个堆算法由编译时选择的 `heap_1.c` 到 `heap_5.c` 决定。

## 任务控制块

每个任务都有一个 TCB，也就是任务控制块。TCB 保存任务栈顶、优先级、任务名、任务状态链表节点、事件等待链表节点，以及可选的运行时统计、互斥量、任务通知、MPU、SMP 亲和性等字段。

其中最关键的是两个链表节点。

`xStateListItem` 表示任务当前处于哪个调度状态列表中。例如就绪列表、延时列表、挂起列表。

`xEventListItem` 表示任务是否正在等待某个内核对象。例如等待队列有数据、等待队列有空间、等待事件组某些位满足条件。

这两个节点让一个任务可以同时表达“调度状态”和“正在等待的对象”。例如一个任务因为队列为空而阻塞时，它的状态节点会挂进延时相关列表，事件节点会挂进该队列的接收等待列表。

## 就绪与运行

FreeRTOS 按优先级维护就绪任务。核心结构是 `pxReadyTasksLists[]`，每个优先级对应一个链表。

调度器选择任务时，先找到最高的非空优先级列表，再从该列表取下一个任务运行。同优先级的多个任务在同一个列表中轮转，因此在启用时间片时可以共享 CPU。

如果 `configUSE_PORT_OPTIMISED_TASK_SELECTION` 为 0，内核使用通用方式从当前最高优先级向下扫描。如果该配置为 1，移植层可以用处理器指令或位图快速找出最高就绪优先级。

## 阻塞与延时

任务主动调用延时 API，或在队列、信号量、事件组等对象上等待时，会从就绪列表移出，进入阻塞状态。

延时等待依赖两张延时列表：当前延时列表和溢出延时列表。因为 tick 计数会回绕，FreeRTOS 用两张表区分“在当前 tick 周期内会到期的任务”和“需要等 tick 回绕后才到期的任务”。当 tick 溢出时，两张表交换角色。

调度器还维护 `xNextTaskUnblockTime`，它记录最近一个会到期的阻塞任务时间。这样 tick 处理时不必每次扫描所有阻塞任务。

## 唤醒与抢占

任务被唤醒通常有几种来源。

1. 延时时间到期。
2. 队列从空变为非空，唤醒等待接收的任务。
3. 队列从满变为有空间，唤醒等待发送的任务。
4. 信号量被释放。
5. 事件组位满足等待条件。
6. Stream Buffer 或 Message Buffer 的另一端写入或读走数据。
7. ISR 调用 `FromISR` API 唤醒任务。

唤醒任务时，内核会把任务从事件等待列表和阻塞状态列表中移除，再加入对应优先级的就绪列表。如果被唤醒任务优先级高于当前运行任务，在抢占式调度下会触发 yield，请求尽快切换上下文。

## 调度器挂起期间

有些内核路径会暂时挂起调度器，以便批量处理状态变化。在调度器挂起期间，内核不能立即把任务放回普通就绪列表，否则会破坏调度器状态。

这时被唤醒的任务会先进入 `xPendingReadyList`。当调度器恢复时，内核再把 pending ready 里的任务合并回正常就绪列表，并根据优先级决定是否需要切换任务。

## Tick 与上下文切换

系统 tick 是 FreeRTOS 时间推进的基础。每次 tick 到来，内核会增加 tick 计数，检查是否有延时任务到期，并根据配置处理时间片轮转。

真正的上下文切换由移植层完成。内核只表达“需要切换”的意图，例如调用 `portYIELD_WITHIN_API()` 或 `portYIELD_FROM_ISR()`，具体如何保存寄存器、切换栈、恢复下一个任务上下文，由当前 CPU port 实现。

## SMP 下的补充逻辑

当 `configNUMBER_OF_CORES` 大于 1 时，调度器需要同时考虑多个核心。TCB 中会记录任务当前运行在哪个 core，或者是否被标记为需要 yield。

SMP 场景下，唤醒一个高优先级任务不一定只影响当前 core。内核可能需要请求另一个 core yield，使更高优先级任务尽快获得运行机会。任务亲和性配置也会限制某些任务只能在指定 core 上运行。

## 从一个队列唤醒看完整链路

一个典型链路如下。

1. 任务 A 调用接收队列 API，但队列为空。
2. 任务 A 的事件节点挂入队列的 `xTasksWaitingToReceive`。
3. 任务 A 的状态节点进入阻塞列表，调度器切换到其他任务。
4. 任务 B 或 ISR 向队列发送数据。
5. 队列代码发现有任务正在等待接收，于是请求调度器移除事件列表中的最高优先级等待者。
6. 任务 A 被移回就绪列表。
7. 如果任务 A 优先级更高，内核触发 yield。
8. 移植层完成上下文切换，任务 A 从接收队列 API 返回。

这条链路体现了 FreeRTOS 的核心协作方式：内核对象负责判断条件是否满足，`tasks.c` 负责改变任务状态，移植层负责真正切换 CPU 上的执行上下文。
